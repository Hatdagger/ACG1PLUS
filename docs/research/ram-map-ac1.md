# Armored Core — RAM map (US, SCUS-94182 v1.0)

Generated by `tools/ram_map.py` from `docs/research/ram-map.toml`. **Edit the TOML, not this file.**

One place for every named RAM address. The details stay in the lane docs named in *Source*;
this map only says what each address is, how sure we are, and where to read more.

**Status:** `tested` = checked in a running game · `code` = read from the game's code ·
`cheat` = from cheat codes only · `guess` = needs a check. **Exe refs:** reads (R), writes (W) and
address-takes (P) found by a static scan of the boot exe's own code (`generated/`, or the exe file with `--exe`), with the
routines. **Module refs:** the same scan over the disc-loaded engines (menu FDAT 201, missions FDAT 202, link FDAT 203, VS FDAT 204):
engine, access kinds, number of routines. For module-area
entries only the engine named in [brackets] is shown, since other engines put other data there;
where a row lists **Other engines**, the same thing's address there (routines paired by code), and
its refs are counted at that address.

**PP rows:** most were carried over from the MoA-US rows by `tools/xdisc/ram_xlate.py` (cross-disc
table `xdisc/globals.tsv`): the address is Phantasma's, the meaning is Master of Arena's until checked on
PP. *Source* says how each address was found (exact / inside / between / near). See
`mapping/foundations.md`.

## Memory layout

| From | To | What |
|---|---|---|
| `80000000` | `8000FFFF` | Kernel / BIOS (not the game's) |
| `80010000` | `80010FFF` | Below the exe |
| `80011000` | `80039FFF` | Exe image: code and data (survives every load) |
| `8003A000` | `8004AD9F` | Exe bss (zeroed at boot, survives every load) |
| `8004ADA0` | `801FFFFF` | Module area (rebuilt on every module load; depends on the engine) |
| `1F800000` | `1F8003FF` | Scratchpad (1 KB fast RAM; fight engines only, nothing lasts past a routine) |

Inside the exe: code `80011000`–`80016F7B` is the game's own, `80016F7C`–`80039C5B` is PsyQ library
code and data (libcd, libspu/libsnd, libgte, libetc/libapi, libgpu, libpad, libc). Library state
is marked *lib*: read it if useful, never write it.

The scratchpad is used only by the fight engines (VS, arena, link, missions, replay share one
layout); the menu and the exe's game code never touch it, and no value in it outlives the routine
that wrote it. Details and the stretches no code was seen using: `mapping/scratchpad.md`.

  `tools/extract_fdat.py`), cached in `ram-xref-modules.json` so the doc rebuilds without the

  module can read as code, so treat single hits with care.
